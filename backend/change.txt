Voice Agent Implementation Steps (Backend)

overall flow ->
  a. Capture (Frontend): Browser API (`MediaRecorder` & `getUserMedia`) records user's microphone.
  b. Send (Frontend -> Backend): Frontend packages recording into a `Blob` (file) and HTTP POSTs it to the `/api/search/voice` endpoint.
  c. Receive (Backend Multer): Multer intercepts the multipart request, validates it is a correct audio format, checks the max file size, and temporarily buffers the file data directly into RAM.
  d. Transcribe (Backend -> Hugging Face): The `searchController` grabs that audio buffer from memory and sends it to the Hugging Face Whisper model API.
  e. Respond: Hugging Face returns the transcribed text; the backend responds to the frontend with the text; node garbage-collects the buffered audio automatically.


  Model being used -> openai/whisper-large-v3


  where are we storing the voice ?
  Multer processes the incoming form data and creates a new object on your request called req.file.

  However, because you are specifically using multer.memoryStorage(), Multer doesn't save the file to your hard drive. Instead, it creates req.file.buffer

1) Added required packages
- Installed `multer` for multipart audio uploads.
  (multer is a middleware which is used to handling form data. Multer adds a body object and a file or files object to the request object. The body object contains the values of the text fields of the form, the file or files object contains the files uploaded via the form)
- Installed `@huggingface/inference` to call Whisper ASR.
- Updated `backend/package.json` and `backend/package-lock.json`.

2) Added upload middleware
- Created `backend/middlewares/upload.js`.
- Used `multer.memoryStorage()` so uploaded audio is available as `req.file.buffer`.
- Added a 10MB upload limit.
- Added MIME-type validation for common audio formats.
- Normalized MIME checks to base type (example: `audio/webm;codecs=opus` is treated as `audio/webm`).

3) Added voice transcription service
- Created `backend/services/voiceService.js`.
- Initialized Hugging Face `InferenceClient` with `HF_ACCESS_TOKEN`.
- Implemented `transcribeAudio(audioBuffer)` using model `openai/whisper-large-v3`.
- Added error mapping for common failures:
  - invalid token (401)
  - model loading (503)
  - rate limit (429)
- Added guard for missing `HF_ACCESS_TOKEN`.

4) Connected controller logic
- Updated `backend/controllers/searchController.js`.
- Imported `transcribeAudio`.
- In `handleVoiceSearch`:
  - validated `req.file`
  - sent `req.file.buffer` to `transcribeAudio`
  - returned transcription as JSON:
    `{ text: <transcribed_text>, message: 'Voice transcribed successfully' }`

5) Wired voice route
- Updated `backend/routes/search.js`.
- Added upload middleware import.
- Updated protected route to:
  `router.post('/voice', checkJwt, upload.single('audio'), handleVoiceSearch)`
- This route flow is:
  auth check -> audio parsing -> transcription handler.

6) Improved global upload error handling
- Updated `backend/middlewares/errorHandler.js`.
- Added handling for `MulterError` and file-size limit with clear responses.
- Added 400 responses for upload validation errors.

7) Environment requirement
- Added/used `HF_ACCESS_TOKEN` in `backend/.env`.
- Voice transcription requires this token.

8) Request contract used by frontend
- Endpoint: `POST /api/search/voice`
- Auth: `Authorization: Bearer <token>`
- Body: `multipart/form-data`
- Audio field name: `audio`

9) Verification done
- Syntax checks passed for updated backend files.
- End-to-end expectation: valid audio upload returns transcribed `text`.
